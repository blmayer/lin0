login

after boot you get a getty on the console (banner from
/etc/issue). default account:

- user: root
- password: lin0

there is no systemd — init is a shell script that
loops getty, which runs login. change the root
password after first boot:

	passwd


users

lin0 ships as a single-user system (root only).
toybox useradd / adduser are not built in; add
accounts by hand.

shipped files:

- /etc/passwd — accounts and password hashes
- /etc/group — groups (root:0, users:100,
  video:44, input:45); member lists start empty
- no /etc/shadow — passwords live in passwd

on a running system, as root:

	# primary group: users (gid 100) from /etc/group
	echo 'name::1000:100:name:/home/name:/bin/sh' 		>> /etc/passwd
	mkdir -p /home/name
	chown 1000:100 /home/name
	passwd name

	# supplementary groups (edit member list; leave
	# empty until you add names):
	#   video:x:44:
	#   input:x:45:name
	# append with sed, e.g. video for framebuffer:
	sed -i 's/^video:x:44:$/video:x:44:name/' 		/etc/group
	sed -i 's/^input:x:45:$/input:x:45:name/' 		/etc/group

	# align device nodes if they are root:root 600
	chown root:video /dev/fb0 && chmod 660 /dev/fb0
	chown root:input /dev/input/event*
	chmod 660 /dev/input/event*

then re-login so id shows the new groups:

	su - name

or type the account name at the getty login prompt.

rules of thumb:

- pick a free uid (1000+)
- primary gid from /etc/group (users=100)
- extra groups: comma-separated after the last colon
  in /etc/group (video=44, input=45)
- shell must be in /etc/shells (default /bin/sh)
- home must exist and be owned by that uid:gid
- group changes apply at next login

to bake accounts into the image, edit etc/passwd
and etc/group in the tree, create the home under
rootfs/home/, then rebuild.


shell history

the login shell is mksh (as /bin/sh). history is
only in memory unless you set HISTFILE.

for a normal user, create startup files in their
home (must be writable by that user).

interactive shells source ~/.mkshrc (or $ENV):

	cat > /home/myuser/.mkshrc <<'EOT'
	export HISTFILE=$HOME/.mksh_history
	export HISTSIZE=2047
	EOT
	chown 1000:100 /home/myuser/.mkshrc

login shells (getty/login, su - user) also run
/etc/profile then ~/.profile. optional:

	cat > /home/myuser/.profile <<'EOT'
	export HISTFILE=$HOME/.mksh_history
	export HISTSIZE=2047
	[ -r "$HOME/.mkshrc" ] && . "$HOME/.mkshrc"
	EOT
	chown 1000:100 /home/myuser/.profile

check:

	su - myuser
	echo $HISTFILE
	# run a few commands, exit, log in again
	fc -l
	cat ~/.mksh_history

notes:

- default HISTSIZE is 2047 if unset; max 65535
- same idea works for root under /home/root/
- if HISTFILE is unset or empty, no file is used


hostname

the name in /etc/hostname is only a file until something
calls sethostname(2). init does:

	hostname -F /etc/hostname

so gethostname(), uname -n, getty's prompt, and most
programs see it. without that step the kernel name stays empty
or (none) even though the file says lin0.

change the name:

	echo mybox > /etc/hostname
	hostname -F /etc/hostname

also keep /etc/hosts in sync if tools resolve the local
name (sudo-like checks, some build systems, hostname -f):

	127.0.0.1	localhost mybox
	::1		localhost ip6-localhost ip6-loopback

default image uses hostname lin0 in both files.


/tmp

many tools (mksh here-docs, ./configure, compilers) create
temporary files under /tmp. that directory must be
world-writable with the sticky bit:

	# mode should be drwxrwxrwt (1777)
	ls -ld /tmp

if you see errors like:

	cant create temporary file /tmp/....tmp: permission denied

then either the directory is not 1777, or it was never
mounted. on a running system (as root):

	chmod 1777 /tmp
	# or use a ram-backed tmp (preferred):
	mount -t tmpfs -o mode=1777 tmpfs /tmp

current lin0 init mounts tmpfs on /tmp with mode 1777 at
boot. the rootfs skeleton also keeps /tmp as 1777 so it
works even before that mount.


networking

default dns ships in etc/resolv.conf. on a
running system:

	vi /etc/resolv.conf

install what you need on the target (for example
wpa_supplicant for wi-fi). lin0 is a starting
point, not a full desktop stack.


passwords

the passwd applet updates /etc/passwd when the
password field is not "x" (shadow placeholder).

	passwd              # change your own
	passwd myuser       # as root: set myuser

there is no /etc/shadow in the default image.
do not set the passwd field to a lone "x" unless
you also create a proper shadow entry.


notes on su / getty

if non-root login or su fails, check the account
first — incomplete users are the usual cause.

- getty does not force root; it prompts and runs
  login with the name you type
- as root, su otheruser needs a valid passwd line
  and a working shell path
- non-root su needs more: toybox setuid root and
  (for toybox su) a modern hash in /etc/shadow —
  the default image is not set up for that
- missing home: login may warn and fall back to /


building software

the on-box compiler is /bin/tcc; /bin/cc is a
symlink to it. use CC=/bin/tcc so libtool sees
basename tcc and fills in shared-link commands.
there is no /usr: put binaries in /bin,
libraries in /lib, headers in /include,
data in /share.

	export PATH=/bin
	export CC=/bin/tcc
	export LD=/bin/tcc
	export AR='/bin/tcc -ar'
	export RANLIB=true

configure scripts should get --prefix=/ so files
land in those directories. AR / RANLIB matter:
libtool calls them, and tcc archives use tcc -ar
with ranlib as a no-op. lin0 has no pkg-config,
so do not install .pc files:

	make install pkgconfigdir=/tmp/pc
	rm -rf /tmp/pc /lib/pkgconfig

prefer .tar.gz sources (no xz applet).
wget works; git is not shipped. toybox
tar does not inflate gzip for you — decompress
first, then extract:

	gunzip make-4.4.1.tar.gz
	tar xf make-4.4.1.tar
	cd make-4.4.1

we want shared libs (.so) in /lib.
for autotools packages that default to both, pass
--enable-shared --disable-static so libtool
only builds .so objects (avoids bogus
.lo errors with tcc). if a build fails
halfway:

	make distclean
	rm -rf .libs objs/.libs
	find . -name '*.lo' -delete

then reconfigure with the same flags. if configure
still rejects tcc, build that one binary elsewhere
for aarch64/musl and copy the .so and headers
in. do not set CC=/bin/cc for libtool-using
packages — basename cc leaves
archive_cmds empty even though the compiler
is tcc.

many tools need a writable /tmp (see above) and
enough space on the root partition — enlarge images
or build on mounted storage when trees get big.


bgce and bgtk

bgce is a minimal
framebuffer compositor; bgtk
is its toolkit. build on the target after the notes in
building software. order matters:
make, zlib, freetype, libxml2, a font, then bgce, then
bgtk. no libdrm required (default backend is
/dev/fb0).

stage work under /home/root/src. hdmi and a usb
keyboard/mouse should be attached:

	ls -l /dev/fb0 /dev/input/event*

downloads (github mirrors redirect; wget follows):

- make-4.4.1.tar.gz
- zlib-1.3.1.tar.gz
- freetype-2.13.3.tar.gz
- libxml2-2.13.5.tar.gz
- dejavu sans: copy DejaVuSans.ttf from another
  machine if needed
- bgce main.tar.gz
  (image ships a fbdev-default snapshot as
  bgce-main.tar.gz in /home/root)
- bgtk main.tar.gz

make (bootstrap if the image lacks /bin/make):

	gunzip make-4.4.1.tar.gz
	tar xf make-4.4.1.tar
	cd make-4.4.1
	./configure --prefix=/ CC=/bin/tcc
	./build.sh
	./make install
	cd ..

zlib, freetype, libxml2 (release
tarballs ship configure). keep the exports from
building software:

	gunzip zlib-1.3.1.tar.gz
	tar xf zlib-1.3.1.tar
	cd zlib-1.3.1
	./configure --prefix=/ --shared
	make
	make install pkgconfigdir=/tmp/pc
	rm -rf /tmp/pc
	cd ..

	gunzip freetype-2.13.3.tar.gz
	tar xf freetype-2.13.3.tar
	cd freetype-2.13.3
	./configure --prefix=/ \
		--enable-shared --disable-static
	grep '^archive_cmds=' builds/unix/libtool
	# with CC=/bin/tcc this should be non-empty
	make
	ls objs/.libs/libfreetype.so.6.20.2
	make install pkgconfigdir=/tmp/pc
	rm -rf /tmp/pc /lib/pkgconfig
	cd ..

	gunzip libxml2-2.13.5.tar.gz
	tar xf libxml2-2.13.5.tar
	cd libxml2-2.13.5
	./configure --prefix=/ \
		--enable-shared --disable-static \
		--without-python
	make
	make install pkgconfigdir=/tmp/pc
	rm -rf /tmp/pc
	cd ..

python is only for optional bindings (on by
default). --without-python builds
libxml2.so / xmllint with no
interpreter. lin0 has no python.

font:

	mkdir -p /share/fonts/truetype/dejavu
	cp DejaVuSans.ttf \
		/share/fonts/truetype/dejavu/

bgtk also reads ~/.config/bgtk.conf if you want to
pin the path.

bgce (installs to /bin, /lib, /include). save
the github archive as bgce-main.tar.gz:

	gunzip bgce-main.tar.gz
	tar xf bgce-main.tar
	cd bgce-main
	make CC=/bin/tcc          # /dev/fb0, no libdrm
	# make CC=/bin/tcc BACKEND=drm   # optional
	make install
	cd ..

	bgce &
	# log: ~/.cache/bgce/bgce.log
	# quit: ctrl+alt+q

optional ~/.config/bgce.conf:

	[background]
	type = color
	color = #336699

	[shortcuts]
	ctrl+alt+q = builtin:exit
	sysrq = builtin:screenshot

bgtk (needs a running bgce for real apps):

	gunzip bgtk-main.tar.gz
	tar xf bgtk-main.tar
	cd bgtk-main
	make CC=/bin/tcc
	make install

	bgce &
	launcher
	# or test_app, terminal, image_viewer,
	# settings

skip gemini_browser unless you also build
openssl (lin0 ships bearssl/libtls, not libssl).
headless ui checks need no display device:

	make headless && ./headless

stock lin0 is root-only, so /dev/fb0 and /dev/input
permissions are fine for bring-up. ignore
ldconfig failures on install — dynamic libs
load from /lib by default.
